# Task: Migrate built-in checks and split the archive flow

## Goal

Put the `repair` construct to work in the shipped workflows: split the OpenSpec archive step into an idempotent transition, a deterministic commit verification repaired by `implementor`, and a separate Validator baseline advance; make `commit-change-plan.sh` replay-safe; add inline or rerun repair to the eight built-in check sites named in the proposal; and document the failure policy for workflow authors. After this task the two runs from GitHub issue 65 (hook-rejected archive commit, draft PR push blocked by a missing `gh` scope) resolve through repair or a blocked pause instead of an opaque abort.

## Background

Read `openspec/changes/failure-recovery/proposal.md` for the issue-65 failure classification and the migration list. The runtime construct exists: a shell or script step may declare `repair` with either `{prompt, session|agent, max}` (inline) or `{rerun: <earlier sibling>}`; a check rerun after repair is the sole success authority; an agent whose final response ends with the line `REPAIR_BLOCKED` stops repair and pauses the run; the inline prompt automatically receives a `<repair-evidence>` block (check stdout, stderr, guarded agent response) with an untrusted-input notice, and `{{repair.check_output}}`, `{{repair.check_stderr}}`, `{{repair.action_response}}`, `{{repair.attempt}}` are available; load-time validation rejects `repair` on non-check steps, rerun targets outside the same sequential scope, and replay ranges containing `break_if` or `skip_if: previous_success`. Verify these by reading `internal/model/step.go` and `internal/exec` before writing YAML.

Built-in workflows live under `workflows/` and are embedded into the binary; workflow YAML and script edits are configuration and do not need TDD, but the scripts in this task have real-Git behavior and get real-Git tests (pattern: `workflows/verify_task_commit_test.go`, which reads scripts through `ReadAsset` and runs them in a temp repository). YAML load tests live in `workflows/embed_test.go`.

Migration list from `openspec/changes/failure-recovery/design.md`:

1. **Archive split.** New hidden sub-workflow `workflows/openspec/archive-change-v1.0.yaml` (follow the hidden-workflow convention used by other `core/` helpers; check `workflows/openspec/_group.yaml` and `workflows/registered.go` for registration) with parameter `change_name`:
   - `archive-transition` (script `archive-transition.sh`, `capture: archive_state`): before touching anything, snapshot the index and worktree for the three allowed path sets (`openspec/changes/<name>`, `openspec/changes/archive/*<name>*`, `openspec/specs`) via `git diff --cached --name-status`, `git diff --name-status`, and the untracked list, and record `start_head`; if the active dir exists, run `openspec validate` then `openspec archive --yes`; resolve exactly one archive dir, exit non-zero on zero or many; compute the transition-owned delta as the worktree change under the allowed paths minus the pre-existing snapshot; print JSON `{archive_dir, change_dir, start_head, owned_delta, prior_index}` to stdout. Idempotent: a second run with the active dir gone and one archive present recomputes the same JSON from the same snapshot file. The snapshot is written to the deterministic path `{{session_dir}}/output/archive-transition/<change_name>.json` (the `session_dir` built-in variable resolves to the run directory; pass it explicitly through `script_inputs` as `session_dir: "{{session_dir}}"` because scripts receive only declared inputs). If the snapshot already exists when the transition runs, reuse it rather than re-snapshotting, so a replay after the move never mistakes the transition's own changes for pre-existing ones.
   - `verify-archive-commit` (script `verify-archive-commit.sh`, inputs `archive_state`, `change_name`, and `session_dir` so it reads the same snapshot file at `{{session_dir}}/output/archive-transition/<change_name>.json` for the pre-existing staged and unstaged state; `repair: {agent: implementor, max: 1, prompt: ...}`): assert the active dir is absent from worktree and index; exactly that archive dir is present; `start_head` is an ancestor of `HEAD`; the committed delta `start_head..HEAD` restricted to the allowed paths equals `owned_delta` exactly; the commit range touches no path outside the allowed paths; the index outside the owned delta equals `prior_index` (pre-existing staged edits, including ones inside `openspec/specs`, are neither committed nor unstaged); the worktree under the allowed paths is clean apart from the pre-existing unstaged edits in the snapshot. Passes with no new commit when the owned delta is already in `start_head..HEAD`. Every failure names the offending path or missing commit on stderr in its first line, because that line becomes the run's failure reason. The repair prompt names the exact owned paths the agent may stage, forbids staging anything else, asks it to follow repository commit conventions and respond to hooks, and carries the old ticket-subject heuristic from `archive-change.sh` as a hint. Use the `[archive] chore: archive openspec documents for <name>` convention from `CLAUDE.md` as the default subject.
   - `advance-validator-baseline` (`command: agent-validator skip`), idempotent.

## Spec

No spec deltas cover workflow YAML (per project convention, workflow migrations are captured in design and tasks). The behavior the migrated sites rely on, from `specs/step-repair/spec.md`:

#### Scenario: Rerun repair on a shell step validates
- **WHEN** a shell step `verify-draft-pr` declares `repair: {rerun: open-draft-pr}` and `open-draft-pr` is an earlier sibling in the same scope
- **THEN** the workflow loads

#### Scenario: Inline repair on a script step validates
- **WHEN** a script step declares `repair` with `session: planning-agent`, a `prompt`, and no `max`
- **THEN** the workflow loads and the step has a repair budget of 1

#### Scenario: Guarded action declares blocked before any repair
- **WHEN** `open-draft-pr` ends its response with `REPAIR_BLOCKED` and `verify-draft-pr` then fails
- **THEN** no rerun happens, the step fails, and the failure evidence includes the `open-draft-pr` response

Issue-65 acceptance criteria for the archive flow (from the proposal and design): exactly one archive directory after the flow; the active directory removed; canonical specs committed; a commit subject accepted by the repository's hook; unrelated staged files untouched; a retry after a successful commit is a no-op.
